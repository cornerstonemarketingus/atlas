# Native paired launch — development acceptance

The bundled mobile/www entry now uses the existing daemon POST /v1/pair/claim and authenticated GET /v1/tasks and /v1/approvals contracts. Pair with a six-digit owner-created code and a trusted HTTPS reverse-proxy origin for the daemon. A local plain-HTTP daemon address is deliberately rejected; deployment of that HTTPS endpoint is an operator prerequisite. This is device pairing, not hosted OAuth/account creation.

The exact pinned Capacitor core module and MIT license are packaged locally in www/vendor. Launch registers SecureStoragePlugin without a browser implementation and refuses pairing on the web platform. The origin and device token are stored together in the native vault, never browser storage. Native HTTP disables redirects, verifies the exact final URL and applies a whole-request deadline. Pairing is never retried automatically after an uncertain response. Disconnect fences late responses and removes this device's locally stored access; it does not revoke the server-side paired-device record. Use the owner device's device settings to revoke a lost or uncertain pairing.

The customer dashboard exposes task and pending approval counts only. Raw backend messages and task internals are excluded. The plus/minus disclosure explains the existing owner-device review route. No approval decision button or biometric grant has been added: exact-action mobile decisions remain dependent on integration with the protected approval boundaries. Existing helpers in PR #61 were inspected and remain untouched; this launcher does not instantiate their browser-cookie or default biometric behavior.

Run mobile/npm test after npm ci --ignore-scripts. For the real packaged page test, set ATLAS_TEST_PLAYWRIGHT to the installed playwright-core index.mjs and ATLAS_TEST_BROWSER to Chromium. Native plugins are emulated at their actual bridge adapter in that browser test; this is not a physical-device or live paired-daemon receipt. Native compilation, secure-vault device acceptance, hosted account login/deletion, push consent/delivery, biometric decisions and production signing/store review remain release gates. Privacy and deletion links lead to the existing hosted instructions; device disconnect does not delete an account.

When updating Capacitor, copy node_modules/@capacitor/core/dist/index.js and LICENSE into www/vendor; the provenance test fails if the packaged runtime differs from the pinned installation. No dynamic remote scripts or global HTTP patch are used.
